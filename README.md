# Лабораторная работа: Автоматизированный сбор данных (Парсинг) и Тестирование на Python

## 🎯 Цель работы
Изучить основы веб-парсинга, автоматического тестирования и работы с сетевыми запросами в экосистеме Python. Получить практические навыки работы с библиотеками `requests` и `BeautifulSoup4` для проведения автоматизированного тестирования.

---

## 🛠️ Технологический стек
* **Язык программирования:** Python 3.X
* **Работа с сетью:** `requests`
* **Парсинг HTML:** `beautifulsoup4` (и lxml)
* **Тестирование:** `unittest` (встроенная библеотека)

## 📋 Техническое задание

Вам необходимо разработать модульное решение, состоящее из трех логических компонентов (модулей/пакетов):

#### Модуль 1: Библиотека классов для работы с базой данных (src/database.py)

Для хранения данных используте встроенную SQLite.

**Требования к базе данных:**
* Таблица `comments` хранит комментарии из всех запусков парсера.
* Поля таблицы и ограничения:
  * `parse_id` и `id` — составной первичный ключ (`PRIMARY KEY (parse_id, id)`), где `parse_id` — номер операции парсинга, а `id` — идентификатор комментария на исходном сайте.
  * `name` — `TEXT NOT NULL` (строка, логин пользователя, ограничение до 256 символов).
  * `message` — `TEXT NOT NULL` (строка, текст сообщения с HTML-разметкой, ограничение до 8096 символов).
* Таблица `parsing_operations` выдает уникальный номер каждому запуску и позволяет сохранять комментарии с одинаковыми ID с разных страниц или запусков.

**Интерфейс репозитория (класс `DatabaseRepository`):**
Реализуйте класс, который принимает путь к файлу БД (или строку `':memory:'` для тестов) в конструкторе и предоставляет 5 обязательных методов:
1. `get_by_id(parse_id: int, comment_id: int)` — получение записи по составному ключу. Если записи нет — возвращает `None`.
2. `get_by_name(username: str)` — получение списка всех записей, оставленных пользователем с конкретным `name`.
3. `add(parse_id: int, comment_id: int, username: str, message: str)` — добавление новой записи с валидацией типов и длины строк. Возвращает `True` при успехе.
4. `update(parse_id: int, comment_id: int, new_message: str)` — изменение поля `message` у записи по составному ключу (с валидацией длины новой строки).
5. `delete(parse_id: int, comment_id: int)` — удаление записи по составному ключу; при успешном удалении возвращает `True`.
6. `get_all()` — получение всех записей для режима просмотра.

Для создания каждого запуска репозиторий также предоставляет `create_parse_operation(source_url: str)`, возвращающий новый `parse_id`.

### Модуль 2: Веб-парсер (Компонент сбора данных)
Реализуйте класс `ForumParser`, предназначенный для извлечения информации со страниц форумов или структурированных веб-ресурсов (например, темы на форумах вроде 4PDA, Habr или специализированных тестовых песочницах).

**Требования к парсеру:**
1. Использовать библиотеку `requests` для скачивания HTML-кода страницы. Обязательно передавать заголовки (`Headers`), включая `User-Agent`, для предотвращения блокировок.
2. Использовать `BeautifulSoup` для разбора структуры HTML.
3. Метод `parse_page(url: str)` должен автоматически находить на странице:
   * **ID сообщения** (уникальный номер комментария, зашитый в атрибутах элементов или ссылках).
   * **Логин автора** (текстовое имя пользователя).
   * **Текст сообщения** (содержимое поста, можно с сохранением внутренней HTML-разметки).
4. Метод `save_to_db(parsed_data, repository)` должен сохранять собранные сущности в базу данных через методы `DatabaseRepository`.

### Модуль 3: Автоматизированные тесты (`unittest`)
Создайте тестовые сценарии для проверки корректности работы репозитория данных и парсера.

**Требования к покрытию:**
* Минимум **2 тест-кейса на каждый метод** работы с БД (`add`, `get_by_id`, `get_by_name`, `update`, `delete`).
  * *Пример для add:* Тест на успешное добавление + Тест на выброс исключения при дублировании ID.
  * *Пример для update:* Тест на успешное изменение существующей записи + Тест на попытку обновить несуществующий ID.
* Минимум **2 тест-кейса для парсера** (проверка корректности извлечения данных из заранее сохраненного HTML-файла-слепка/фикстуры, чтобы тесты не зависели от стабильности сети интернет).

## 🚀 Руководство по настройке и запуску

### 1. Терминал
Откройте терминал в корневой папке проекта — там, где находятся `README.md`, `requirements.txt` и каталоги `src/` и `tests/`. Все следующие команды выполняются из этой папки.

### 2. Создание виртуального окружения (`venv`)
Виртуальное окружение — отдельная папка с интерпретатором Python и установленными для проекта пакетами. Оно изолирует зависимости лабораторной работы от других проектов и системного Python. Создание окружения:

  ```bash
  python -m venv .venv
  ```

Для Windows PowerShell активируйте его командой `.\.venv\Scripts\Activate.ps1`; для `cmd.exe` используйте `.\.venv\Scripts\activate.bat`. В macOS/Linux команда активации — `source .venv/bin/activate`. После активации приглашение терминала обычно начинается с `(.venv)`. Активация нужна, чтобы команды `python` и `pip` указывали именно на окружение проекта.

### 3. Установка необходимых библиотек
`requests` выполняет HTTP-запрос, `beautifulsoup4` разбирает HTML, а `lxml` служит быстрым HTML-парсером для BeautifulSoup. Установка точного набора зависимостей проекта:
```bash
python -m pip install -r requirements.txt
```

### 4. Фиксация зависимостей
Файл `requirements.txt` уже содержит прямые зависимости приложения. Команда `python -m pip freeze` выводит версии всех пакетов установленного окружения; перенаправление этого вывода в файл полезно для отдельной фиксации точных версий, но обычно заменяет список прямых зависимостей полным списком пакетов.

### 5. Запуск программы и тестов
Запуск консольного меню:
```bash
python -m src.main
```
Каждый успешный запуск парсинга получает новый номер операции; поэтому одинаковые ID комментариев с разных запусков не конфликтуют. Ключ в интерфейсе БД отображается как `parse_id-id`. Пункт просмотра базы данных доступен только для чтения. При первом запуске база будет создана в `data/comments.sqlite3`; существующая база со старой схемой автоматически мигрирует записи с номером операции `0`. События записываются в `Logs/parser.log`.

Для автоматического поиска и выполнения всех тестов из папки `tests/` выполните:
```bash
python -m unittest discover -s tests
```
