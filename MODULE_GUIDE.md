# Пояснение к модулям (для ознакомления)

Этот файл — отдельная шпаргалка по устройству проекта, а не часть задания для сдачи.

- `src/database.py` — репозиторий SQLite. Он выделяет ID операции парсинга, хранит записи с составным ключом `(parse_id, id)`, проверяет значения и предоставляет операции добавления, поиска, изменения и удаления. При первом запуске на старой БД переносит существующие комментарии под ключом `0-id`.
- `src/parser.py` — получает HTML по HTTP, извлекает идентификатор, автора и разметку сообщения, затем передает результат репозиторию. Сетевой запрос ограничен тайм-аутом и содержит `User-Agent`.
- `src/main.py` — точка запуска и консольное меню. При каждом успешном получении страницы создается новая операция парсинга; в просмотре БД составной ключ отображается как `parse_id-id`. Меню использует `DatabaseRepository.get_all()` и не выполняет SQL-запросы напрямую; операции изменения в UI не предлагаются.
- `src/logger/config.py` — единое место настройки логирования: формат, уровень, вывод в консоль и файл `Logs/parser.log`.
- `tests/test_database.py` — проверяет методы репозитория и их граничные случаи на временной базе `:memory:`.
- `tests/test_parser.py` — проверяет разбор локального HTML-снимка; тесты не зависят от доступности сайта.
- `tests/fixtures/forum_page.html` — небольшой пример разметки форума для воспроизводимых тестов.
- `requirements.txt` — внешние библиотеки проекта.

## Как проходит парсинг

1. Меню получает введенный пользователем HTTP/HTTPS-адрес.
2. `ForumParser` скачивает страницу через `requests` с заголовком `User-Agent` и проверяет HTTP-статус ответа.
3. `BeautifulSoup` разбирает HTML и ищет блоки сообщений, их ID, автора и содержимое. Внутренние HTML-теги сообщения сохраняются.
4. Репозиторий создает новый ID операции, а `save_to_db` передает его вместе с ID каждого комментария в `DatabaseRepository.add`.
5. Репозиторий валидирует данные и записывает их в SQLite; успешные операции отражаются в журнале.

## Примеры для проверки

На момент проверки (11 ноября 2026 года) эти публичные страницы открывались с HTTP 200 через используемый приложением `requests` и содержали разметку обсуждений, которую понимает текущий парсер:

- [Python Discussions: тема с ответами](https://discuss.python.org/t/is-cpython-sovereignty-at-risk/110006)
- [Django Forum: приветственная тема](https://forum.djangoproject.com/t/welcome-to-the-django-forum/7)

Оба форума работают на Discourse: парсер находит блоки `#post_...`, имя автора и текст сообщения. Ни один внешний сайт нельзя гарантировать от будущих ограничений, временных сбоев или региональных блокировок: HTTP 403 может зависеть от сети, частоты запросов и политики сайта. Приведенные ссылки успешно открывались при проверке; используйте умеренную частоту запросов и соблюдайте правила площадок. У других сайтов могут отличаться HTML-селекторы.
